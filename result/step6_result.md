# 6단계 성능 측정 결과

측정일: 2026-10-23 · 장비: Jetson Orin Nano Super 8GB · venv `~/eg2` (`torch.cuda.is_available()` = True)

측정 방법: 테스트를 돌리는 동안 다른 터미널에서 `sudo tegrastats --interval 1000` 실행. 지연은 두 번째 실행 값.

| 구성 | 로드 크기 | 로드 후 RAM (MB) | 입력 | 지연 (ms) | GPU 사용률 (%) |
| --- | --- | --- | --- | --- | --- |
| 텍스트 전용 | 270M | 약 4,900 (대기 약 3,600 → +약 1,300) | 질의 2개 | 187 (dim=768) / 179 (dim=256) / 179 (dim=128) | 0~23 (대부분 0) |
| +비전 | 440M | 약 5,800 (대기 약 3,700 → +약 2,100) | 이미지 5장 | 6,223 | 최대 99% (이미지 인코딩 순간 1~3초) |
| +비전 | 440M | - | 동영상 10초 | 실패 (`torchcodec` 설치 후에도 FFmpeg 라이브러리 로드 실패) | - |
| +오디오 | 570M | 약 5,500 (대기 약 3,500~3,800 → +약 1,700~2,000) | WAV 4개 | 13,824 | 최대 17% (대부분 0) |
| 전체 | 740M |  | 혼합 |  |  |

## 메모

- **텍스트 전용**
  - RAM: 실행 전 대기 상태 약 3,590 MB, 실행 중 최고 4,931 MB (첫 실행 최고 4,830 MB). 종료 후 약 3,600 MB로 돌아옴.
  - 지연: 첫 실행 dim=768은 262 ms (CUDA 준비 시간 포함)라 두 번째 실행 값을 적음.
  - GPU: `GR3D_FREQ`가 대부분 0%, 잠깐 22~23%. 질의 2개는 GPU가 몇 ms만 일하고 끝나서, 1초 간격 측정에는 거의 잡히지 않음. 지연 대부분은 토크나이저·Python 처리(CPU 코어 하나 100%)로 보임.
  - 검색 결과: 두 질의 모두 모든 차원에서 정답 문서가 1위 (CO2 문장, 에어컨 문장).
  - 스왑이 이미 약 3,190 MB 사용 중이었음 (다른 프로그램이 메모리를 쓰고 있을 가능성).
- **+비전 (이미지 5장)**
  - 지연: 4단계 첫 실행 32,045 ms → 이후 8,614 / 9,360 / 6,223 / 7,081 / 7,835 ms. 연속 실행(`&&`)의 두 번째 값 6,223 ms를 표에 적음. 실행마다 6~9초로 차이가 있음.
  - RAM: 대기 약 3,700 MB, 실행 중 최고 5,896 MB (첫 실행) / 5,768 MB (두 번째 실행). 끝나면 약 3,700 MB로 돌아옴.
  - GPU: 대부분 0%, 이미지를 인코딩하는 1~3초 동안 99%까지 올라감. 텍스트보다 GPU 일이 훨씬 많아서 tegrastats에 잡힘.
  - 검색 결과: 4단계와 같음 (빈 강의실 → frame_01, 앉아 있는 사람 → frame_05 1위).
- **+비전 (동영상)**: 4단계에서 `torchcodec`이 없어 실패. 6단계에서 `pip install -c ~/eg2/torch-pin.txt torchcodec`으로 설치했지만 `Could not load libtorchcodec` 오류. 젯슨에 깔린 FFmpeg 8에 `libswscale.so.9`(영상 크기 변환 라이브러리)가 빠져 있어서 torchcodec이 FFmpeg를 불러오지 못함 (torch 2.14.1+cu132). README 대안대로 같은 동영상에서 뽑은 프레임 5장(이미지 행)으로 대체.
- **+오디오**
  - 지연: 5단계 첫 실행 56,173 ms, 두 번째 20,009 ms. 6단계에서 연속 실행 12,997 / 13,824 ms. 연속 실행의 두 번째 값 13,824 ms를 표에 적음.
  - RAM: 실행 중 최고 5,629 MB (첫 실행) / 5,502 MB (두 번째 실행). 끝나면 약 3,500 MB로 돌아옴.
  - GPU: 대부분 0%, 잠깐 3~17%. 비전(99%)과 달리 GPU를 거의 쓰지 않는데도 더 느림. 오디오 파일을 읽고 변환하는 CPU 쪽 처리가 대부분의 시간을 쓰는 것으로 보임.
  - 검색 (6단계 실행): 날카로운 경보음 → beep.wav 정답. "덥다고 냉방을 요청하는 목소리" → mic.wav (0.657), "웅웅거리는 배경 소음" → mic.wav (0.683)로 noise.wav를 찾지 못함.
  - 5단계 실행 때 검색: beep·noise 질의 정답, "사람이 말하는 소리" → speech 정답, 내용 질의 "덥다고 냉방을 요청하는 목소리"는 실패 (noise·mic 동점 0.657).
- **전체**: 아직 실행하지 않음.
- GPU 클럭이 611 MHz로 찍힘. 최대 성능 모드(`sudo nvpmodel -m 0`, `sudo jetson_clocks`)가 꺼져 있으면 지연이 더 길게 나올 수 있음.
